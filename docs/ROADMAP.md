# Roadmap — Agent Readiness Inspector

По `docs/spec.md` (ревизия 2026-07-30, фактчек — `docs/spec-review.md`).
Правило готовности этапа: у каждого — проверяемый Definition of Done; «готово»
выносит независимая проверка (`npm run check`, фикстуры, живой прогон), не
утверждение. Размеры относительные: S — дни, M — неделя±, L — больше.

## M0 — check-engine (M)

Чистое TS-ядро всех проверок §3 + скоринг + калибровка. Ноль браузерного API.

- Типы и реестр проверок уже заведены (`src/checks/`); каждая проверка §3 —
  функция на `CheckContext`, анти-false-positive валидаторы тела обязательны
  (правило: статус-код открывает проверку, pass выносит только валидатор).
- **Конфиг матрицы** (версионируемый): список чеков, категории, on/off-дефолты
  (llms.txt info, A2A off), пороги уровней 0–5, формула композита
  (чек-взвешенная гипотеза §4 — подтвердить/опровергнуть калибровкой).
- **Фикстуры**: снятые реальные ответы (spintax.net, cloudflare.com, github,
  vercel, operator.chatgpt.com soft-404) + синтетические краевые случаи
  (пустой robots, HTML-заглушка под 200, `keys: []`).
- **Калибровочный харнесс** (скрипт, не расширение): прогнать наш движок и
  сравнить с web-UI isitagentready на 10–20 сайтах; снять точный состав
  категорий и Auth.md/A2A/ACP-детекты живого тула; двойной источник
  (web-UI + `/api/scan`) с логом расхождений CF-vs-CF.

DoD: `npm run check` зелёный; на калибровочном наборе наш композит/уровень
совпадает с web-UI (или расхождение объяснено и записано в конфиге).

**Статус (2026-07-30): M0 ВЫПОЛНЕН.** 22/22 проверки, 142 теста, фикстуры 5
реальных сайтов, `npm run calibrate` против живого isitagentready: **0
необъяснённых расхождений, уровни совпадают на всех референсах** (spintax L4,
cloudflare L3, vercel L2). Четыре документированных расхождения в направленном
ALLOWLIST (`scripts/calibrate.mts`): dnsAid/webMcp (локально непроверяемы до
M1) и mcpServerCard/a2aAgentCard (мы принимаем de-facto формы, CF фейлит
собственный сайт). Калибровка встроена в drift-watch CI отдельным джобом.
Калиброванные семантики (oauth absent→fail, WBA empty→na, AI-rules wildcard)
внесены в §3 спеки.

Честная оговорка о базисе: харнесс сверяется с `/api/scan`
(машиночитаемая поверхность). Web-UI, по которому спека велит калиброваться,
расходится с `/api/scan` на границе L4/L5 (spintax 79: UI L5 vs api L4 в один
день) — ручная сверка с web-UI и решение, чью сторону показывать юзеру, — часть
подготовки M1.5.

## M1 — главная поверхность: скан текущей вкладки (M)

Поверхность — модель RI (спека §6): один HTML в двух режимах — **side panel в
Chrome/Edge** (клик по иконке открывает панель; `default_popup` вырезан
манифест-хуком, `sidePanel` permission) и **попап + sidebar_action в Firefox**.

- Probe-layer в SW: `fetch` с таймаутом <30с на пробу, `credentials: 'omit'`
  для well-known проб, `include` — только для рефетча самой страницы; детект
  «3P-cookies заблокированы» → индикатор «скан без сессии» (§11).
- UI: композит + уровень + категории + чеклист pass/fail/na с evidence по
  каждой пробе; копия фикс-промпта (`navigator.clipboard`, по жесту); ссылки на
  стандарты. Стиль Lighthouse, css из RI (`theme.css`/`popup.css`).
- Библиотека фикс-промптов v1 в бандле, ключ = `check.id`.
- Локали: en + ru реальные тексты.

DoD: живой прогон на spintax.net / за-логином странице / SPA-soft-404 сайте даёт
корректные вердикты; e2e-смоук через глобальный playwright.

**Статус (2026-07-30): M1 ВЫПОЛНЕН** (за-логином кейс — вручную при M1.5:
детект блокировки 3P-cookies перенесён туда, поле `session` в протоколе
зарезервировано). Живой смоук `scripts/e2e-smoke.mts` (bundled Chromium,
расширение собрано и загружено по-настоящему): spintax.net → 75/L4
Agent-Integrated (цифра в цифру с калибровкой M0-5), operator.chatgpt.com →
0/L0. Смоук поймал реальный UI-баг ([hidden] vs display:flex) — остаётся
постоянным инструментом DoD. Firefox-долг записан в TODO под M1.5.

## M1.5 — стор-бета (S, календарно долгий — запускаем сразу после M1)

**Гейт на вход: калибровка M0 зелёная** — на калибровочном наборе наш скор
совпадает с web-UI Cloudflare, либо каждое расхождение объяснено и записано.
Value prop «зеркалим Cloudflare» хрупок, если мы не можем объяснить дельту —
попап, который «просто работает», сам по себе сабмит не открывает.

Privacy policy, локализованные листинги, оптимизированные скриншоты и свои
иконки, ревью-ноты с обоснованием `<all_urls>`. Пакеты всех целей собираются
Linux workflow из одного тега; локальные архивы в сторы не подаются.

**Статус (2026-08-02): v0.1.0 ПОДАН ВО ВСЕ ТРИ СТОРА, РЕВЬЮ ИДЁТ.** Chrome,
Firefox AMO и Microsoft Edge получили пакеты из
[GitHub Release v0.1.0](https://github.com/investblog/agent-readiness-inspector/releases/tag/v0.1.0).
Privacy policy опубликована через GitHub Pages, тексты и ассеты зафиксированы в
`docs/store-listings/` и `store-assets/`. Этап закроется после решений сторов и
добавления публичных ссылок на листинги; до этого статус не означает публикацию.

## M2 — dashboard (L)

Сохранённые сайты, батч-скан (чанки под 5-минутный кап SW-события), история и
графики, настройки (конфиг проверок, интервалы). Сюда же — **лёгкая форма CF
Connect** (вставка токена/curl-автопарс + verify) и **внешний скан** URL Scanner
с диффом «изнутри vs снаружи» (§5, §8.1) — первая точка, где нужен токен.

DoD: батч 20+ сайтов не убивает SW; внешний скан живьём против реального
аккаунта; дифф отображается.

**Статус (2026-07-30): M2 ВЫПОЛНЕН** (план — `.agents/plans/done/m2-dashboard.md`).
Три этапа с ревью: storage-слой (схема v1, приватность истории в единственной
точке записи, retention 50), дашборд (таблица, батч 2×+stagger с прогрессом и
отменой, SVG-спарклайны, options_ui), настройки + CF Connect + дифф
«изнутри vs снаружи» по официальному URL Scanner. 187 тестов; смоук:
батч двух сайтов даёт 75/42 — совпадает с калибровкой M0-5. Открыто: живой
внешний скан требует CF-токена юзера (TODO).

## M2.5 — repair kits (M, в основном контент)

Spec §8.0. На каждый fail — переносимый repair kit по `check.id`: SKILL.md
(формат совместим с CF `skillUrl`), stack-рецепты (Cloudflare, Vercel, Netlify,
nginx, Next.js — стек детектим по уже читаемым заголовкам), проверочные команды
и ожидаемый evidence в терминах наших валидаторов — цикл замыкается ресканом.
Пишем по спросу: top-fail проверки (markdown-негошиэйшн, Content Signals,
robots/AI-боты) × основные стеки; остальное итеративно. Хостинг — см. §13
(киты тянут к 301.st, бандл — минимальный фолбэк).

Порядок с M3 гибкий: это контент-работа, её можно вести параллельно кодовым
этапам. Синергия с M4: fix-apply использует те же рецепты как предпросмотр
изменений.

DoD: kit хотя бы для 3 top-fail проверок × 3 стеков; применение рецепта на
тестовом сайте переводит проверку fail → pass при рескане.

## M3 — watch-режим (M)

Alarms-рескан watch-листа (≥1 мин, реалистично — часы), диф против прошлого
скана, runtime-запрос `notifications` по жесту, алерт на регресс (pass→fail,
скор ниже порога), таймлайн в дашборде. Ключевой отличитель — если M2 затянется,
минимальный watch (лист + алерты, без графиков) можно вытащить вперёд: от M2 ему
нужно только хранилище истории.

DoD: искусственный регресс на подконтрольном сайте порождает нотификацию.

**Статус (2026-07-31): M3 ВЫПОЛНЕН** (план — `.agents/plans/done/m3-watch.md`).
Два этапа с ревью: диф регрессов + storage v2 (сравнение с последним не-`na`
вердиктом, гистерезис на падение уровня, миграция без потери данных v1) и
планировщик + алерты (пачки с курсором под кап SW, дедуп «объявили один раз»,
сброс после починки, уведомления за opt-in разрешением, бейдж регресса как
запасная поверхность). Проверено вживую и закреплено смоук-сценарием: alarm
1440 мин, регресс `authMd,oauthDiscovery|L4`, реальное уведомление. 226 тестов.

## M3.5 — иконка как поверхность: скор при браузинге + инбокс мониторинга (S)

Иконка работает без открытия панели. Скор текущей вкладки при браузинге
(авто-скан — **opt-in**, по умолчанию выключен: это запросы к каждому открытому
сайту) и счётчик непрочитанных сообщений мониторинга в другом стиле (`!N`,
синий). Приоритет явный: непрочитанный алерт > скор — иначе при включённом
авто-скане алерт не увидели бы никогда. Пометка прочтения — «прочитано =
увидено»: инбокс на дашборде гасит бейдж, но строки остаются подсвеченными.

DoD: живой регресс зажигает `!1`, открытие дашборда гасит бейдж, скор
возвращается; выключение настройки действительно снимает нарисованные бейджи.

**Статус (2026-08-01): M3.5 ВЫПОЛНЕН** (план — `.agents/plans/done/m3.5-ambient-badge.md`).
Ревью нашло два BLOCK: бейдж вкладки — три независимых оверрайда (text/colour/
title), сброс одного текста оставлял алерт в цвете скора с его тултипом; и кэш
авто-скана в памяти SW живёт ~30 секунд, то есть обещанный TTL «раз в 10 минут»
на деле означал скан на каждое переключение вкладки — кэш переехал в
`storage.session`. 253 теста, смоук из 7 сценариев.

## M4 — fix-apply + полный CF Connect визард (L, advanced)

Минт зонных токенов (§8.1: bootstrap → `POST /user/tokens` → verify → удаление
bootstrap), детект CF-сайта, применение фиксов через CF API с предпросмотром,
подтверждением и откатом; матрица «какой fail → какой фикс» (markdown-негошиэйшн,
Content-Signal в robots). Сверить template-links дашборда CF при реализации.

DoD: фикс на тестовой зоне применяется и откатывается; скоупы токена — минимум.

## M5 — слой 301.st (S)

Новостная панель (JSON с 301.st, тянем только при открытом дашборде),
кросс-промо тулов, spintax.net как «живой эталон» (N/A-строки как обучение
стандарту, § 9). Порядок с M4 взаимозаменяем.

## Сквозные треки

- **Drift-watch CI** (GitHub Actions, scheduled; авто-Issues вместо ручных
  репортов — урок debloat, где детект ломался об «просить людей отправлять»):
  - *doc-watch* (можно до M0, как только репо на GitHub): нормализованные
    снапшоты изменяемых источников в `ci/drift/snapshots/` — чек-лист из бандла
    isitagentready, `/api/scan` по референс-сайтам, доки/changelog CF, SEP-2127,
    IETF-драфты (datatracker), agent-skills-rfc и ai.robots.txt (GitHub API),
    contentsignals.org, ucp.dev. Дифф → Issue с лейблом `drift` + автокоммит
    снапшота; дедуп — комментарий в открытый Issue того же источника, не новый.
    Нужен только `GITHUB_TOKEN` (`issues: write`).
  - *calibration* (из M0 — постоянный): еженедельный прогон харнесса; алерты
    «мы разошлись с CF» и «CF разошёлся сам с собой» (маркетинг-факты §11) —
    тоже Issues.
  - Пререквизит: push репозитория на GitHub.
- **Локализация**: en+ru → 7 локалей RI перед публичным релизом.
- **Дрейф матрицы**: новые проверки живого тула → обновление конфига, не кода.
- **Решения по ходу**: имя и монетизация (§13) — надо решить до M1.5 (листинг);
  хостинг промптов/весов — до M2 (пока бандл).

## Порядок и критический путь

M0 → M1 → M1.5 (сабмит, ждёт параллельно) → M2 → M3 → M4 ⇄ M5;
M2.5 (repair kits) — контент-трек, идёт параллельно любому этапу после M1.
Критический путь до публичной беты: M0 + M1 + M1.5. Всё после — итерации поверх
уже живого расширения.
