## Goal
Полная страница дашборда: сохранённые сайты со свежим скором, батч-скан
(открытые вкладки или список), история сканов со спарклайнами композита,
настройки (опциональные проверки, CF-токен), внешний скан через официальный
URL Scanner API с диффом «изнутри vs снаружи».
DoD (ROADMAP): батч 20+ сайтов не убивает SW; внешний скан живьём против
реального аккаунта; дифф отображается; гейт + смоук зелёные.

## Архитектурные решения (зафиксировано на планировании)

1. **Storage-слой строится ПЕРВЫМ и общий с M3-watch** — M3 потом получает
   историю/лист бесплатно. `chrome.storage.local`, типизированный модуль
   `src/shared/storage.ts`, схема с `schemaVersion: 1` + migration-hook.
   - `sites: Record<origin, { addedAt: number; lastScanAt?: number }>`
     (поле `watch` НЕ добавляем сейчас — M3 добавит миграцией, чтобы схема
     не врала о несуществующей фиче);
   - `history:<origin> → ScanSnapshot[]` (ключ на сайт, чтобы не переписывать
     один гигантский объект): снимок = `{ scannedAt, composite, level,
     statuses: Record<CheckId, CheckStatus> }` — **без evidence** (тяжёлый и
     воспроизводимый ресканом; диф M3 работает по статусам);
   - `settings: { checkOverrides?: Partial<Record<CheckId, boolean>>;
     cfAccountId?: string; cfToken?: string }`;
   - **retention**: максимум 50 снимков на сайт (FIFO-prune при записи) —
     квота storage.local ~10MB, `unlimitedStorage` НЕ берём (минимальные
     скоупы, §10); ~50 снимков × ~1KB × 100 сайтов ≈ 5MB — запас двукратный.
2. **Батч оркеструется страницей дашборда, не service worker'ом.** Дашборд —
   живая вкладка: шлёт `scan`-запросы последовательно (конкуренция 2, пауза
   ~1с между сайтами — politeness), каждый скан — отдельное SW-событие
   заведомо < 5-минутного капа. SW-капы обходим архитектурой, а не keepalive-
   трюками.
3. **Запись истории**: сканы попадают в историю ТОЛЬКО для сохранённых сайтов
   (privacy: браузинг-история юзера не копится молча). В панели — кнопка
   «сохранить сайт»; сохранённый сайт → каждый скан (panel/batch) пишет снимок.
   Панель шлёт тот же `scan`; запись в storage делает background (единая точка).
4. **Графики — vanilla SVG-спарклайны** (polyline композита по времени), без
   чарт-библиотек (bundle size, CSP). Перед вёрсткой графиков загрузить
   dataviz-скилл (правило триггера).
5. **Внешний скан — ТОЛЬКО официальный URL Scanner API** (`agentReadiness:
   true`, токен юзера; spec §8.1 лёгкая форма: вставка токена/curl-автопарс +
   `/user/tokens/verify`). Неофициальный `/api/scan` в прод не тащим (решение
   ревью спеки). Дифф: их чек-статусы vs наши по одинаковым id, раскраска
   расхождений + известные (dnsAid/webMcp/mcp/a2a) помечаются «expected».
6. **Entrypoint** `src/entrypoints/dashboard/` + `options_ui: { page:
   'dashboard.html', open_in_tab: true }` (спека: «полная страница / options»).
   Кнопка в хедере панели → открыть дашборд. CSS на токенах theme.css.
7. **Settings → движок**: `checkOverrides` мапятся в `RunOptions.include`
   (llmsTxt/a2a on/off); передаются в `scan`-запросе (протокол расширяется
   полем `include?: CheckId[]`, вычисляет background из settings — решить на
   этапе a: чтение settings в background проще и единственная точка правды).

## Steps

1. **M2-a — storage-слой + сохранение сайтов (S/M).**
   `src/shared/storage.ts` (schema v1, typed API: sites CRUD, appendSnapshot с
   prune, settings get/set, migrate()); background пишет снимок после scan для
   сохранённых сайтов; кнопка «сохранить сайт» в панели; settings.checkOverrides
   учитываются в handleScan.
   → verify: юнит-тесты storage (fake chrome.storage + prune + migrate),
   тесты background-интеграции; гейт зелёный. → **reviewer → фиксы → commit**.
2. **M2-b — дашборд: сайты, батч, история (L).**
   Entrypoint + options_ui; таблица сохранённых сайтов (скор/уровень/дата,
   пересканировать, удалить); «добавить открытые вкладки» + ручной ввод origin;
   батч-оркестрация с прогрессом и отменой; спарклайны истории (dataviz-скилл
   перед вёрсткой); i18n en/ru; smoke-сценарий в e2e-скрипте (открыть дашборд,
   добавить сайт, батч из 2, проверить историю).
   → verify: гейт + расширенный смоук; скриншот-ревью UI.
   → **reviewer → фиксы → commit**.
3. **M2-c — настройки + CF connect light + внешний скан с диффом (M).**
   Вкладка настроек (тогглы llms.txt/A2A; форма токена: вставка/curl-автопарс
   по regex 301-ui, verify, статус); кнопка «внешний скан» на сохранённом
   сайте → POST urlscanner/v2/scan → поллинг результата → таблица диффа
   inside-vs-outside с «expected»-пометками; секреты: токен в storage.local,
   в логи/evidence не попадает (secrets-ревью обязательно).
   → verify: живой прогон с реальным CF-токеном (нужен от юзера) + фикстурный
   тест диффа; гейт. → **reviewer → фиксы → commit**.
4. Закрытие: ROADMAP/TODO статусы, план → plans/done/, смоук-прогон полный.

## Риски / открытые микрорешения
- Квота storage.local: retention 50 — калибруем по реальному размеру снимка
  на этапе a (тест на размер).
- Батч по вкладкам требует `tabs.query({})` по всем окнам — URL уже видимы
  через host_permissions; фильтруем http(s) и дедуп по origin.
- URL Scanner: лимит 1 скан/10с (free) — очередь внешних сканов с таймером;
  поллинг результата с бэкоффом (их скан рендерит страницу, до ~минуты).
- Дифф-маппинг: их id совпадают с нашими (проверено калибровкой) — но состав
  может дрейфовать; неизвестные id показываем в блоке «только у CF» (как в
  calibrate.mts).
- M2-c зависит от CF-токена юзера для живой проверки — запросить заранее.
