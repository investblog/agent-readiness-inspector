# M3.5 — Ambient badge & alert inbox

<!-- Spec §6/§7. Процесс: этап → ревьювер → фиксы → коммит. -->

## Handoff

- **Готово:** A–D. Storage v3 (инбокс + browsing-настройки), `resolveBadge` как
  чистая функция приоритета, авто-скан по навигации, инбокс на дашборде,
  индикатор в панели. Смоук из 7 сценариев зелёный,
  `badge="!1" -> ""`, `auto-scan badge="42" off->""`.
- **Грабли, которые нашёл ревьювер (и которые дёшево не заметить):**
  - **бейдж вкладки — это ТРИ независимых оверрайда** (text/colour/title).
    Сброс одного текста оставлял `!2` красным, с тултипом «42 · L2». Поэтому
    алерт красится и глобально, и по каждой вкладке — никакой опоры на
    fallback-семантику;
  - **`text: null` ≠ `text: ''`**: пустая строка гасит вкладку насовсем и прячет
    глобальный алерт, `null` — возвращает к глобальному;
  - **кэш в памяти SW живёт ~30 секунд.** TTL-обещание «один скан на сайт в 10
    минут» без `storage.session` превращалось в «скан на каждое переключение
    вкладки» — то есть в трафик к чужим сайтам кратно больше обещанного;
  - выключение «показывать скор» не гасило уже нарисованные бейджи: единственная
    активная вкладка в этот момент — сам дашборд, `normalizeOrigin` даёт `null`,
    и перерисовывать было нечего;
  - `visibilityState` не ловит окно на втором мониторе — прочтение без просмотра.
    Нужен ещё `document.hasFocus()`;
  - **два подметания бейджа гоняются на самом частом переходе.** Алерт приходит,
    когда дашборд открыт → он же читает его через десятки миллисекунд → два
    `refreshBadges` по O(вкладок) await'ов чередуются, и на части вкладок
    остаётся `!1`, при этом флаг «состояние актуально» уже выставлен, и починить
    некому. Лечится сериализацией + поколением, и флаг ставится ТОЛЬКО после
    полного прохода;
  - **пересборка бейджа на каждом пробуждении SW** (а его будит любое
    переключение вкладки) стирала нарисованные скоры. Текст бейджа переживает
    смерть SW, но не рестарт браузера — значит, пересобирать надо на
    `onStartup`/`onInstalled`, а не на старте модуля.

## Goal

Иконка расширения должна работать без открытия панели: показывать **скор текущей
страницы при браузинге** и **число непрочитанных сообщений мониторинга**. Оба
режима управляются из настроек, у сообщений появляется состояние «прочитано».

Запрос юзера: «нужно в настройки вынести авто-скан и что-то еще, чтобы отображать
при браузинге. Туда же в другом стиле стоит количество сообщений из мониторинга и
продумать пометку прочтения».

## Ключевые решения

### 1. Один бейдж — две роли, приоритет явный

Бейдж физически один, поэтому нужно правило, а не «как получится»:

- **Скор** — per-tab (`setBadgeText({tabId})`), цвет по зоне (good/mid/low),
  текст = число. Принадлежит странице, снимается при навигации.
- **Алерты** — глобальный бейдж (`setBadgeText` без tabId), текст `!N`
  (`!9+` при >9), синий `#1D4ED8`.
- **Приоритет: алерты > скор.** Непрочитанный регресс — событие, требующее
  действия, и оно исчезает само после прочтения; скор — фоновая информация,
  которая восстановится на следующем скане. Обратный приоритет означал бы, что
  при включённом авто-скане алерт не виден НИКОГДА (каждая навигация красит скор).
- Chromium: per-tab текст перекрывает глобальный. Поэтому при появлении нового
  алерта per-tab тексты гасятся по всем вкладкам (`tabs.query` → clear), иначе
  вкладки со скором продолжат прятать `!N`.
- **Различие не только цветом** (правило a11y проекта): префикс `!` + свой
  tooltip. Скор `8` и алерт `!8` не спутать даже в ч/б.

### 2. Авто-скан — выключен по умолчанию

Скан каждой открытой страницы = сетевой запрос к каждому сайту, куда зашёл юзер.
Это ровно то, что privacy-правило проекта запрещает делать молча, поэтому:
`autoScan: false` по умолчанию, включается осознанно, в подсказке честно сказано,
что это те же запросы, что и ручной скан.

Ограничители: только активная вкладка, только http(s), single-flight на origin,
TTL-кэш 10 минут (возврат на вкладку не порождает новый скан). История по-прежнему
пишется только для сохранённых сайтов — правило живёт в `appendSnapshot`, менять
нечего.

### 3. Инбокс сообщений и пометка прочтения

Сейчас алерт живёт только как `lastAlertSignature` на сайте — сосчитать нечего.
Появляется список `alerts` (schema v3, FIFO 50):

```
{ id: `${origin}|${signature}`, origin, at, signature, levelDelta,
  compositeDelta, regressions[], readAt? }
```

Пишется в `runWatchCycle`, **до** уведомления и независимо от него: инбокс —
основная поверхность для тех, кто не дал разрешение на notifications.

**Пометка прочтения — «прочитано = увидено»:**
- список алертов на дашборде помечает показанные алерты прочитанными
  автоматически (бейдж гаснет сразу), но строки, которые были непрочитанными на
  момент рендера, остаются подсвеченными до ухода со страницы — информация не
  теряется, как в почтовом клиенте;
- авто-пометка ждёт `visibilityState === 'visible'` — вкладка, открытая в фоне,
  не «прочитывает» алерты;
- явные действия: «×» на строке (убрать одну) и «очистить» (весь инбокс).
  Кнопки «отметить прочитанным» нет — она была бы дублем автопометки.
- удаление сайта удаляет и его алерты (как и историю) — сирот не остаётся.

## Этапы

- **A. Данные** — storage v3: `alerts` + `browsing` настройки, методы, тесты.
- **B. Бейдж и авто-скан** — чистая функция приоритета `resolveBadge`, покраска в
  background, авто-скан по навигации. Тесты на приоритет и формат текста.
- **C. UI** — блок настроек «При браузинге», инбокс на дашборде, счётчик на
  кнопке дашборда в панели, i18n en/ru.
- **D. Проверка** — unit + живой смоук (алерт → `!1` → прочтение → скор).

## DoD

`npm run check` зелёный; смоук покрывает обе роли бейджа; ревьювер без BLOCK;
настройки по умолчанию не меняют текущее поведение (авто-скан выкл).
